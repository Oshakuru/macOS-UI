# Decisions log

## 2026-11-17: direction
- **Concept B (Balanced Hybrid)** is the working direction.
- **Light theme first**; dark later as a recolour pass plus manual adjustments.
- **Visual refinements (v2):**
  - Whiter panel (`#F5F5F7`, edge `#C7C7CC`).
  - Rounder geometry: 5-px panel and hotbar corners (curved staircase), 2-px slot corners, rounded selection ring.
  - Buttons: graphite `#1D1D1F`; hover in Apple blue `#0071E3` (white text ≈ 4.7:1); disabled `#48484A`.
  - Tooltip and hotbar stay dark, because vanilla draws white text on them.
- **Button shape:** both variants are kept for in-game testing, rounded rectangle (5 px) and full pill (10 px).

## Phase 0: verified from the 1.21.11 client jar
- `version.json`: resource pack format **75.0**.
- 523 GUI PNGs; the full list is in [vanilla-1.21.11-gui-sprites.tsv](vanilla-1.21.11-gui-sprites.tsv).
- `container/inventory.png`: 256×256 canvas, panel 176×166 at (0,0). 46 slot frames plus the 51×72 player preview at (25,7). Each slot frame's top-right and bottom-left corner pixels are `#8B8B8B`.
- `hotbar` 182×22, `hotbar_selection` 24×23, offhand 29×24 (22×22 box).
- `slot_highlight_back/front`: 24×24, 16×16 content at (4,4), nine-slice border 4.
- `widget/button`: 200×20, nine-slice border 3. `button_disabled`: border 1.
- `tooltip/background`: 100×100, border 9. `tooltip/frame`: border 10 with `stretch_inner`.

## Prototype 0.1: in-game results
- Rounded variant loaded fine. Feedback: the slot grid felt cluttered.
- **Pill variant showed missing textures.** Cause: nine-slice border 10 on a 20-px sprite. **Rule: top + bottom borders must stay below the sprite height.**
- Stray grey dots at slot corners. The hotbar is hard to see against dark terrain at night.

## Prototype 0.2
- Slots are flat 16×16 `#E5E5EA` rounded tiles with a 2-px gap between them.
- Corner dots fixed. Pill border changed to left/right 10, top/bottom 9 (awaiting in-game confirmation).

## Prototype 0.3
- Glass player area: real transparency (α 120 at the top, fading to α 60), a `#D1D1D6` edge and a specular rim. Vanilla can't blur, so the glass tints the world rather than frosting it.
- To verify in game: partial transparency renders as expected.

## 0.3 in-game results
- The glass player area renders real transparency. User asked for it to be more transparent.
- Buttons render correctly in the game menu.

## Prototype 0.4
- **Hotbar → macOS Dock** (user request): dark translucent fill (`#2C2C2E`, α 150), a thin light rim (white α 46), a soft dark edge and 7-px corners. No per-slot boxes. The selection is a soft highlight plus a 2×2 white indicator dot under the item. The light rim also addresses the hotbar's poor contrast at night.
- Glass player area: α 72 at the top, fading to α 32.

## Prototype 0.5: Liquid Glass
- The user's reference is **Apple Liquid Glass** (iOS 26 / macOS Tahoe), not the smoked-glass Dock of 0.4.
- **Pixel translation:** clear tinted body + specular rim (key light top-left, echo bottom-right) + inner lensing band + floating shadow, generated by `liquid_glass()` in `tools/build.py`.
- **Not possible in vanilla:** blur, refraction and motion-reactive highlights. The material relies on real transparency plus static highlights.
- **Dock magnification requested** (enlarge the selected item). **Not possible:** item render size is hardcoded. Substitute: the selected slot is a raised, brighter glass bubble that pokes 1 px above the bar. The indicator dot was removed.

## 0.6: button shape decided
- **Pill buttons** (10-px corners; nine-slice border left/right 10, top/bottom 9). Rounded rectangle dropped. One pack (later renamed `macOS-UI-Light`).

## 0.7: creative inventory and recipe book
- Creative screens use the same container system (`repaint_container()`).
  - **Search field is dark**, because vanilla draws its text white (same rule as buttons).
  - Destroy-item slot: red tile (`#FFE3E1`) with an Apple-red (`#FF3B30`) ×.
  - Tabs: selected = panel fill, merging into the panel; unselected = `#D8D8DD`; 5-px rounded outer corners.
  - Scroller: `#AEAEB2` pill.
- **Recipe book button** (user request): panel-coloured button; the book's green ramp is mapped to the accent blue ramp (`book.map` token).

## Name
- **"macOS UI" is the official pack name** (user decision, 2026-11-17). Pack zip: `macOS-UI-Light.zip`; in-game title: "macOS UI — Light".

## 0.8: HD HUD, magnification, recipe book
- **In-game feedback (0.7):** the 1× Liquid Glass hotbar looked chunky ("not slick"); the recipe book screen was still vanilla; the creative scrollbar was too thick; magnification was requested again.
- **HD for the HUD:** GUI sprites render at their logical size whatever their resolution, so the hotbar sprites are now 4× (e.g. `hotbar.png` 728×88) and drawn with a signed-distance-field renderer. **Open question:** move every panel to HD for consistency?
- **Magnification is possible after all:** the client item model definition condition `minecraft:selected` is true when the item is selected on the hotbar, and `oversized_in_gui` (1.21.6+) lets the bigger model draw past the slot. Selected items in the GUI display context use a child model whose `display.gui.scale` is ×1.25 (`magnify.scale` token).
  - **Side effects to check in game:** the selected item probably also appears magnified in the inventory's hotbar row. Packs that replace `items/*.json` will conflict with ours. Item textures from other packs still work.
- **Recipe book:** the recipe area stays dark because vanilla draws the page counter in white. Text fields are dark for the same reason.

## 0.8 in-game results
- **Working:** the selection bubble (4×, 96×92), the offhand (4×, 116×96) and **hotbar magnification**.
- **Broken:** the 4× `hotbar.png` (728×88) rendered as the missing texture. Working hypothesis: a size limit around 512 texels per sprite side (unconfirmed; check `latest.log`). 0.8.1 uses 2× (364×44) for the hotbar.

## 0.9: magnification only
- User decision: **no selection bubble**. The selected slot is indicated only by Dock-style magnification, now at **1.5×** (a 24-px item in a 20-px slot pitch, so it just touches its neighbours).
- To check in game: whether the selected slot is still obvious enough without a frame, the overlap with neighbouring items and stack counts, and the inventory's hotbar row (18-px pitch, so slightly more overlap there).

## 0.10
- Magnification **1.38×** (user tuning after 1.5×).
- **No white outline on the hotbar or offhand** (user decision). The Liquid Glass rim stays only on the player-preview glass.

## 0.11: silver apple food icons
- User request: replace the food drumsticks with the golden apple, made silver. The 16×16 item can't shrink cleanly to the 9×9 HUD icon, so the apple is redrawn by hand (`APPLE` grid in `tools/build.py`). The palettes are the `food.*` tokens. No Mojang texture is copied.
- The Apple logo itself is not redrawn for HUD icons; only the user's own artwork is used, for the pack icon.

- **Approved:** the silver apple food icons (user, 2026-11-17).

- **Hunger effect:** blue apples instead of green (user decision).

## 0.13: sliders
- The track stays dark (vanilla draws slider labels in white). The knob is grey `#AEAEB2` rather than white, because the label can sit over the knob. Hover: blue knob plus a blue track edge.

## 0.14: optional Respackopts settings
- **User decision:** support the Respackopts mod as an **optional bonus**. The pack must still work unmodded with the defaults; this keeps the "no mod dependencies" rule.
- **Mechanism:** `.rpo` files with a `condition` (and a `fallback` file where an alternative exists) plus a folder `.rpo` on `assets/minecraft/items/` for magnification. No resource expansion (`${…}` placeholders) is used, because vanilla would read the placeholders as broken JSON.
- Alternatives are generated by `build_options()` into `assets/macos_ui/alt/`.
- **Not yet tested with the mod installed.**
